# 林木视频语音内容整理：AI产品PRD

# B. 视频二：AI 产品的 PRD 怎么写

核心：AI PRD 和传统 PRD 的区别，不是“传统 PRD 多加一章 AI”。

## 完整语义整理

AI PRD 首先仍然要回答业务价值在哪。

但 AI 产品多一个关键问题：

> **为什么一定要用大模型？**

需要说清：
- 大模型在这个场景里的不可替代性是什么；
- 是效果更好、成本更低、输入更复杂、规则无法穷举，还是开放语义/多模态必须依赖模型；
- 传统方案为什么不够。

以电商素材生成为例：
先梳理核心业务问题；
拿数据说明问题；
再说明 AI 素材为什么可行，而不是先上模型再找理由。

之后仍需要竞品分析和产品目标。

### 业务目标 vs 模型目标

智能客服业务目标可能是：
- 问题解决率提升；
- 人工成本下降；
- 服务效率提升。

模型目标可能是：
- 回复准确率；
- 对话轮次；
- 拒答/升级人工；
- 任务完成质量。

模型目标必须服务业务目标。

### 需求和流程
PRD仍要写核心功能、优先级、性能、响应速度、安全和数据需求。

业务流程是用户视角的操作步骤和业务执行落地步骤。

系统流程尤其重要。
Agent要标出：
- 大模型调用节点；
- 工具调用节点；
- 判断/路由节点；
- 人工介入节点；
- 异常处理分支。

### 模型选型
重要原则：
**从小参数模型开始验证；效果相似时优先小模型。**

Agent多个节点可用不同模型：
- 复杂推理强模型；
- 分类/抽取小模型；
- 主模型 + 备用模型；
- latency / cost / QPS / context / structured output / multimodal 共同决定。

### Prompt 工程
Prompt必须文档化管理，不能当“调试时再说”。

PRD应明确：
- System Prompt角色；
- 能力边界；
- 输出约束；
- 核心指令；
- 示例；
- Prompt策略；
- 版本管理。

硬规则：
**未经评测的 Prompt 不能直接上线。**

### 评测体系
评测是 AI 产品的核心专业资产之一。

需要：
- 数据来源；
- 核心/边界/对抗/安全场景比例；
- MVP/灰度/全量所需评测规模；
- 每个维度评分方式；
- 人评、自动规则、LLM-as-Judge组合；
- Prompt/模型升级/Bad Case触发回归。

不能只写“准确率”。

### 效果保障与稳定性
模型输出到用户看到结果之间要有质量控制：
- Structured Output / Schema；
- 格式校验；
- 后处理；
- 多次采样/一致性；
- RAG引用；
- cross-check；
- 置信度/拒答；
- fallback；
- timeout；
- 限流；
- cache；
- failover。

### AI能力边界
PRD要明确：
- 能做到什么；
- 做不到什么；
- 已知缺陷；
- 当前版本不修什么；
- 哪些必须人工确认。

### 数据飞轮
用户使用 → 数据采集 → Bad Case → 评测集更新 → 问题归因 → Prompt/模型/流程优化 → 效果提升。

### 上线与运营
还要考虑：
- 灰度/AB；
- 成本；
- 回滚；
- 风险。

AI PRD可以很细，但实际工作按项目风险和阶段裁剪，不要求每次写满所有章节。
