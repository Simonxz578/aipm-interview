# 《大模型产品模板：需求文档（PRD）》完整结构化整理

来源：用户上传的14页PDF。以下是完整结构和信息要点的整理版，用于面试复习，不是原PDF的逐字复制。

# 文档前言
- PRD不一定每次都写得同样全面；
- 不同公司文档习惯不同，按需裁剪；
- 示例版本命名采用大版本 + 重点功能迭代 + 小更新；
- 文档以具体功能/版本命名。

# 一、背景

## 1. 需求背景类型
- 业务价值：说明需求收益，必要时附BRD；
- 用户体验：说明体验价值和验证方式；
- 问题修复：小问题可直接Bug处理，大问题再单独PRD。

## 1.1 业务背景
描述现状、痛点、机会。

## 1.2 为什么用大模型
AI PRD的核心新增问题。
需要说明：
- 为什么不能只用规则、传统ML或人工；
- 大模型在当前场景的不可替代性；
- 传统方案局限；
- AI方案效果/成本/ROI。

## 1.3 竞品分析
建议字段：
竞品、技术方案、模型选型、核心差异、效果水平。

## 1.4 产品目标
分：
- 业务目标
- 模型目标

# 二、需求描述

先给需求总览和优先级。
P0最高，P1/P2依次降低。

## 2.1 需求清单
字段：
序号、优先级、需求点、需求描述。

## 2.2 需求分类

### 功能需求
如语言理解/生成、多领域支持等。

### 性能需求
示例维度：
- 首Token延迟
- P95
- QPS
- 并发
- 可用性

### 安全需求
用户数据、隐私、加密、访问控制、数据出境等。

### 数据需求
- 埋点：执行链路和用户操作；
- 正负Case：接受/不接受；
- 业务数据：用于验收功能价值。

# 三、业务流程图
从用户视角画操作步骤/业务流程，可用流程图或泳道图。

# 四、系统流程图
展示系统间数据和动作链路。

AI产品特别标：
- LLM调用节点：模型和预期延迟；
- Tool/API调用；
- 判断/路由；
- 人工介入；
- 异常处理。

# 五、模型选型

核心思想：
模型选型是在业务约束里做最优解，不是单看“最强”。

## 5.1 约束
示例：
- 成本预算
- 延迟
- 部署方式
- 数据要求
- 许可
- 微调
- context
- multimodal/tool能力

## 5.2 模型对比
按参数规模、推理能力、延迟、成本、输出稳定性等比较。

同类型模型做盲测，并周期复验。

## 5.3 结论
说明：
- 主模型
- 备用模型/failover
- 选型理由
- 成本估计
如果多个节点需要模型，可节点级分别选。

# 六、Prompt工程

Prompt属于核心交付物之一，需要文档化和版本管理。

## 6.1 System Prompt
- 角色
- 能力边界
- 输出约束
- 核心指令
- 完整示例

## 6.2 Prompt策略
可按任务使用few-shot、推理引导、结构化输出、JSON/XML、任务拆解等。

## 6.3 版本管理
记录：
版本、变化、评测结果、上线状态、日期。

关键要求：
**Prompt变更必须跑评测，达标才能灰度；未经评测不直接上线。**

# 七、训练数据集 / 知识数据
如果涉及微调或知识库，记录：
- 知识数据
- 参考示例
- 约束
- Good Case
- Bad Case
并和算法团队确定格式。

# 八、评测体系

作者强调评测集是AI产品的重要资产。

## 8.1 构建
来源：
- PM人工构造
- 真实用户query
- LLM生成+人工筛
- 线上Bad Case

覆盖：
按真实上线场景比例划分核心、边界、对抗、安全等。

规模：
MVP、灰度、全量逐步扩大，持续补充。

## 8.2 维度与标准
通用例：
准确、完整、格式、安全、表达等。
可按业务加权。
安全可设一票否决。

## 8.3 样例
覆盖：
- 单轮正向
- 单轮负向
- 多轮正向
- 多轮负向

## 8.4 执行
方式：
- PM自评
- 专业人工
- 自动评测/LLM-as-Judge
- 规则

触发：
- Prompt变化
- 模型升级
- Bad Case累计
- 周期性回归

## 8.5 持续维护
- Bad Case回流；
- 新场景同步补用例；
- 版本管理；
- 定期清理过期case。

# 九、效果保障与稳定性

## 9.1 输出质量
如：
结构化输出、格式校验、后处理、重试、规则判断。

## 9.2 幻觉治理
如：
RAG引用、cross-check、置信度/拒答、人工确认。

## 9.3 稳定性
如：
超时、重试、主备模型、限流、缓存、熔断。

## 9.4 一致性
控制temperature/top-p等；必要时固定seed；关键事实由外部规则/工具确定。

# 十、原型图

AI交互特别关注：
- 等待/加载
- 结果不确定性
- 用户反馈
- 编辑
- 重试
- 人工介入

# 十一、AI能力边界

写清：
- 能做到
- 做不到
- 已知缺陷
- 当前不解决的问题

作用：
管理研发、业务和用户预期。

# 十二、数据飞轮

## 12.1 用户反馈
显式：点赞、评价、文字反馈。
隐式：结果采纳、编辑、重试、停留等。

## 12.2 监控/告警
示例：
自动失败率、模型调用失败率、响应时间、安全拦截等。

## 12.3 回流
用户使用
→ 数据采集
→ Bad Case标注
→ 评测更新
→ 问题归因
→ 模型/Prompt优化
→ 效果提升。

并要求周期汇总、评估和清理。

# 十三、上线与运营

## 13.1 灰度 / A/B
定义：
阶段、流量、持续时间、观察指标、进入下一阶段条件。

## 13.2 成本
监控：
- Token
- API
- 推理/GPU
- 人工
- 单次请求/成功任务成本

## 13.3 回滚
定义触发条件、步骤和影响范围。

# 十四、风险与应对
按风险类型、概率、影响、应对策略记录。
可包括：
模型、隐私、安全、业务、成本、依赖。
