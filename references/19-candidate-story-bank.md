# 候选人故事库

本文件用于动态选证据，不是背诵稿。事实分级与公开来源以[个人证据库](05-candidate-profile.md)为准；回答结构见[答案组织与深度](18-interview-answer-architecture.md)。使用一个主案例，最多一个辅助证据，优先覆盖本题最重要的能力。

**组装规则**：已做行动可用“我做了”；当前判断用“我现在会”；未实施方案用“如果我负责/重做，我会”。每个故事区分已确认行动、可讲的判断、待确认细节。具体事故、对话、冲突、时间成本或KPI没有来源就不补造。强弱证据不是候选人的能力评分。

## 1. 经纬恒润：工业AI与工程约束

### One-line story

在PCB器件封装检查相关流程中，参与大模型部署评估与RAG/Agent集成，让模型在专业资料和内网约束下工作；候选人材料记载相关环节效率提升50%以上。

### Problem / user / business context

2024年7–8月AI硬件方向实习，小米SU7相关PCB器件封装检查。直接用户是执行专业检查的工程人员。模型输出要能进入已有工程流程，专业信息、图像理解、输出稳定性与数据保密都构成约束。原材料没有说明整条产线规模或业务预算。

### Task / ownership

可确认的个人贡献是大模型需求拆解、部署调试、多模型评估、检索与Agent工作流集成；不是整条产线负责人。问答表D6提到与清华团队推进，但分工、汇报关系和具体人员未明确，不扩写管理职责。

### Key actions：已确认

1. 部署、调试和评估GLM-4、GLM-4V、Qwen1.5-14B、GPT-4o，比较任务效果、部署方式与稳定性。
2. 比较本地部署和API，结合内网运行与数据保密限制选择方案；不能倒推某模型最终用于所有生产节点。
3. 梳理LLM/Agent相关研究，将检索、网页抓取、多模态处理等能力整合进workflow；阅读数量和代码量不替代成果。
4. 把RAG-based retrieval应用到PCB相关检查，让模型利用专业信息并按明确步骤处理，结合既有口径中的专业校验和Bad Case评估。
5. 用相关流程效率验证实际价值。结果仍须保留“相关环节”范围，不能扩写为公司级收益。

### Technical / product decisions

主判断：工业可用性取决于任务表现、保密、部署及复核成本的共同约束。可以解释本地方案增加部署维护，API受数据授权、网络和服务依赖限制。RAG补专业知识，workflow约束步骤，校验承接确定性要求；各层用途说清即可，不必堆所有架构名词。

### Evidence / result

strong evidence：问答表D6/D8和原证据库支持上述任务、模型与集成工作，相关环节效率提升50%+为候选人材料口径。

weak evidence：缺少基线工时、任务样本、复核时间、具体漏检与误报数，不能承诺准确率。被追问统计细节时应坦率说明现有材料无法给出精确口径，再说明需要怎样验证，不能临时创造一组数。

### Difficult trade-off / Bad Case

已确认难点是开放模型能力与工业流程要求的差距，以及本地/API选择。可讨论专业知识不足、视觉理解和输出稳定性作为评测方向；尚无一条可核对的具体失败日志，不说“某天系统漏掉某器件，我立刻修复”等情节。

### Reflection / if-redo

反思口径：先明确任务和评价维度，再比较模型与部署方案，最后看复核后的流程价值。若重做，会更早记录人工基线、失败类型、模型版本及端到端工时，把50%+的测量边界留清楚；这是改进建议，不说已经做过完整仪表盘或对照实验。

### 困难题组装

What：专业检查对模型可控性、隐私与效率同时有要求。Why：某个模型演示效果好，不足以决定能否进内网和工程流程。How：先围绕任务比较部署与模型表现；再用RAG、workflow和校验补专业约束；最后用相关流程效果验证。How Better：更早冻结评价样本和效率口径。没有证据时，不给过去行动硬加实验规模。

### Ability tags / best-fit questions

analysis_planning、prioritization、learning_agility、innovation。适合模型选型、多模态、API与本地、RAG、Agent、工业ROI、项目困难、技术协作。leadership/influence需另有真实协作情节才能使用。

### Prohibited claims / uncertainty

禁止把PCB流程写成自动驾驶算法研发、整车量产责任或公司后续AI产品；不声称零漏检、无人审核、节省某金额；不以1000行代码证明影响。2025/2026公司公开背景与2024个人经历严格分开。

## 2. Ninefold Physics：0→1与教育Agent

### One-line story

独立推进情境化物理AI Tutor的产品定义、状态与模型/规则分工、开发部署和公开Beta，用可运行学习流程验证产品机制。

### Problem / user / business context

面向中学物理、海外A-Level等学习场景。直接给解答容易跳过学生的推理过程；用户完成一道题，不足以证明理解。学生需要适度帮助，教师与家长关注正确性和学习目标。当前阶段是public beta / prototype evidence，不是已证明商业规模的产品。

### Task / ownership

已有口径支持Simon独立推进产品定义、学习流程、reasoning state、Agent/Prompt、规则校验、Bad Case与fallback，以及Codex辅助开发部署。辅助开发方式可交代，主要价值讲自己的任务定义、设计取舍和验证。

### Key actions：已确认的产品机制

1. 定义观察、预测、解释、AI追问、确定性计算/动画验证的学习流程，以Rain/Leaf等情境让学生先暴露自己的理解。
2. 将语音/文字回答用于判断reasoning state，从first divergence选择最需要追问的缺口，而非一次批改整段并给出完整解法。
3. 设计渐进提示和已会学生的快通道，学生需要多少帮助取决于当前状态，不能把每个人都锁进完整hint chain。
4. 将语义理解与物理正确性分开：模型解释学生表达，Physics Toolkit与规则检查可确定的公式、数值、单位和边界；课程、难度和学科范围限制开放生成。
5. 推进Bad Case评测、fallback与公开Beta。可以讲这些设计维度，未经提供的日志、故障次数、测试规模或上线比例不能自行补充。

### Technical / product decisions

固定教学流程提供边界，Agent在边界内根据状态决定追问、提示、前进或调用工具。单Agent+工具能做到就不为“高级”增加角色；Multi-Agent需要说明独立校验、隔离或并行的实际收益。已会学生的快通道体现学习支持与交互成本的取舍。

### Evidence / result

strong evidence：公开Beta、可运行学习流程、状态驱动机制和确定性校验，来源为既有候选人材料。

weak evidence：尚无大规模学习成效、付费、留存及有对照的学习增益。公开Beta并未在本次独立重测所有功能；面试中可讲已确认设计，不能推成全量稳定运行的数据结论。

### Difficult trade-off / Bad Case

追问太少容易替学生思考，过多又会阻碍已经会的学生。错误定位、语音识别和物理校验分别可能失败。可用“如果把正确思路误判为错误……”讲风险与处理设计，不编造一次真实上线事故。无法可靠判断时澄清输入、回到可验证步骤或限定提示，避免把错误解释继续传递。

### Reflection / if-redo

反思口径：教学目标决定模型的行动边界，可计算问题交给确定性工具。若重做，更早建立无提示迁移题和延迟复测、记录提示依赖与放弃位置、明确对照条件，再扩大题型。它们是后续验证计划，不能说已经证明学会。

### Ability tags / best-fit questions

demanding_goal、innovation、prioritization、learning_agility。适合代表项目、0→1、Agent与Workflow、为什么AI、防抄作业、如何证明学会、教育Eval、规则边界、学习安全、多学科扩展。个人开发不能自动当成团队领导证据。

### Prohibited claims / uncertainty

不报未经确认的DAU、学习增益、留存、收入、准确率；不把教师采用其他项目的数据移到Ninefold；不声称所有场景已上线或某个提示机制已有因果效果。

## 3. IJSE：研究与产品判断

### One-line story

以第一作者身份分析科学教师的GenAI使用经验，与Michael J. Reiss合作发表论文；通过逐份阅读、编码、主题审查和理论解释，把教师陈述转成有边界的研究发现。

### Problem / user / business context

研究关注教师如何在科学教学中使用GenAI，以及技术、教学法、学科判断和伦理如何共同影响使用。样本来自伦敦某大学硕士课程背景，不代表所有科学教师；教师的自述需要与实际课堂行为区分。[已发表全文](https://www.tandfonline.com/doi/full/10.1080/09500693.2026.2733687)，核验日期2026-09-21。

### Task / ownership

第一作者身份与分析行动由全文Data analysis明确支持：反复阅读转录材料、初始编码、整理候选主题、与原始材料比对并进行理论解释。各分析阶段与第二作者讨论；没有证据时不把全部招募、访谈及所有修订归为个人独立完成。

### Key actions：已核实

1. 反复阅读每份访谈转录，记录初步观察，熟悉材料，关注教师描述的具体经验。
2. 对相关片段进行初始编码，把相近内容整理为候选主题，利用图或表检查编码与主题关系。
3. 对照编码片段与完整数据审查主题，合并重叠内容、检查主题之间的关系，最终定义8个主题。
4. 在归纳主题之后，用GenAI-TCK、GenAI-TPK和GenAI-TPACK作第二阶段解释；保留跨维度重叠，避免强行把所有片段塞进单一分类。
5. 在分析过程中与第二作者讨论不确定解释，回查原始资料，保证主题有材料支撑。可用于collaboration，不扩写不存在的争执或具体对话。

### Technical / product decisions

研究先从材料形成主题，再进入理论解释。教师端备课与学生端课堂使用的信心不同，讨论指出审核、修改和拒绝输出的控制空间可能是相关因素。产品推论是分开设计备课辅助与课堂互动的控制方式，并验证审核负担；这是应用判断，不能冒充已证明的产品因果关系。

### Evidence / result

strong evidence：题名、双作者、IJSE、2026-09-18在线发表、Open Access与DOI已经全文核实。研究使用20位教师的英文半结构访谈，16位中国籍；具体任教与招募背景详见个人证据库。论文记录了8个主题及第一作者的分析步骤。

weak evidence：回顾性自述，没有课堂观察或学生访谈；单一大学硕士背景、较窄教龄与国籍分布影响可迁移性；信心评级没有充分效度验证。量表的分数不能被当作客观能力，更不能当作产品KPI。

### Difficult trade-off / Bad Case

可讲的分析难点是材料如何形成有依据的主题，以及如何保留学科、教学法与技术之间的重叠。主题审查、与合作者讨论、回查材料是已记录的处理步骤。不得补造审稿人否定、某参与者争论或招募危机。把“教师说有信心”直接当成产品采用，是需要避免的证据误用。

### Reflection / if-redo

反思：教师能预先检查的生成材料，与课堂实时使用有不同的专业判断和控制要求；产品要区分场景。若做后续研究或产品试点，会补任务观察、实际修改和持续使用记录，扩大情境覆盖并检查量表质量。上述改进不能声称已在本论文实施。

### Ability tags / best-fit questions

analysis_planning、collaboration、learning_agility。适合用户研究方法、复杂材料分析、与合作者校准解释、教师采用、信任、课堂与备课差异、教育AIPM动机。demanding_goal/influence仍需另有真实reviewer/revision或说服行动证据。

### Prohibited claims / uncertainty

不称为英国教师总体样本，不把第一作者等同于全部研究独立完成；不虚构编码一致性系数、审稿轮次、付费意愿、线上留存或学习增益。论文的具体研究方法可以讲，“这一定能提升产品留存”仍需另行验证。

## 4. 选案例与换案例

| 题目中心 | 默认主案例 | 可用辅助证据 |
| --- | --- | --- |
| 工程约束、模型比较、工业ROI | 经纬恒润 | Ninefold的模型/规则分工 |
| 0→1、Agent、学习流程、教育评测 | Ninefold | IJSE研究视角 |
| 教师采用、用户研究、教育动机 | IJSE | 长期教学或Ninefold |
| 影响他人、组织协作 | 先找真实行动最具体的既有案例 | Formal Hall等；不按标签编冲突 |

连续两题尽量换主案例；面试官追问同一项目时保持连续。能力相同可以换场景验证，事实不够时缩短故事并明确局限。
